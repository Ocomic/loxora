# Loxora RFCs

RFCs document foundational proposals, philosophies, terminology, architecture, and governance before implementation.

Before changing a foundational RFC, review [`CROSS-REFERENCES.md`](./CROSS-REFERENCES.md) to understand dependencies and affected areas.

## Current RFCs

- RFC-000 — Why Loxora?
- RFC-001 — Project Philosophy
- RFC-002 — Core Concepts & Terminology
- RFC-003 — Knowledge Lifecycle
- RFC-004 — Development Workflow
- RFC-005 — Project Preparation
- RFC-006 — Knowledge Navigation & Progressive Context
- RFC-007 — Initial Architecture and Hackathon MVP Boundaries — **Accepted for Hackathon MVP; current baseline per RFC-008**
- RFC-008 — Post-Hackathon Governance and Work Authorization — **Accepted**
- [RFC-009 — Mission Concept and State Model](./RFC-009-mission-concept-and-state-model.md) — **Accepted**
- [RFC-010 — Product UI Shell and Mission Control MVP](./RFC-010-product-ui-shell-and-mission-control-mvp.md) — **Accepted**
- [RFC-011 — First Launch, Setup, and Xora](./RFC-011-first-launch-setup-and-xora.md) — **Accepted**; milestones 1 (Milestone 12) and 2 (Milestone 13, setup in script mode) implemented; Amendment 1 (setup as a conversation with Xora) implemented as Milestone 14; Amendment 2 replaces the 2D bridge visualizer with the bridge as the ship's chat

RFC-000 through RFC-006 are foundational drafts. RFC-007 was accepted by Ocomic on July 13, 2026 only for explicitly authorized Hackathon MVP milestones; it is not permanent architecture. RFC-008, accepted on October 2, 2026, treats RFC-007, ADR-001, and ADR-002 as the current baseline and defines change classes for post-Hackathon work. RFC-009, accepted on October 2, 2026, defines Missions as execution state separate from knowledge and their state model.
